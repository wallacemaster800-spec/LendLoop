# Before a public launch

This is a take-home implementation, not a claim of production readiness.

1. **Infrastructure and secrets.** Use separate Clerk/Convex production projects, a managed secret store, key rotation and TLS at the n8n reverse proxy. Keep the editor behind private access. Replace the development Compose profile with n8n external task runners and an isolated broker; allow only the modules and variables they need. Use Postgres for n8n, tested backups, health checks and pinned image digests.
2. **Delivery semantics.** The mock channel provides exactly one stored notification per key. An external email provider introduces a new side effect: use its idempotency support, a delivery ledger and reconciliation rather than claiming “exactly once” email. Monitor backlog age, failed runs and missed daily schedules. Send operational alerts to an actual on-call destination.
3. **Scale.** The take-home queries read the neighborhood's listings/loans in full. Add pagination and batch cursors to the catalogue, admin views, activity and overdue scan; do not silently truncate. Partition by neighborhood before adding multiple communities. Index and cap request history access. The existing 20-event worker batch and five-attempt retry limit need load testing.
4. **Abuse prevention.** Add per-identity and IP rate limits at the appropriate boundaries, account verification, moderation/audit history and a proper invitation/admin provisioning process. Current active-listing and pending-request limits prevent casual spam, not sustained abuse. Bound request streams before reading them at the edge.
5. **Browser and account security.** Roll out a tested nonce-based CSP compatible with Clerk, MFA for administrators and a session/device policy. Evaluate Clerk's production origins, redirect allowlists and bot controls. Self-hosted fonts already avoid an extra tracking origin.
6. **Product rules.** Define neighborhood membership, handoff arrangements, deposits, damage disputes, cancellation of approved future reservations and confirmation of returns by the lender. Either participant can currently mark a started loan returned; this is deliberately simple, not dispute protection.
7. **Privacy.** Decide retention periods for loans, archived tools, member identities and logs. Implement account deletion/export and minimize operational logs. There are no addresses or emails stored in the application database. For a healthcare system, revisit the data model, audit controls, vendor agreements and regulatory requirements rather than transplanting this demo or claiming compliance.
